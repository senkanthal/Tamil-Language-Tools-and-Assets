# Security Policy

## Supported Versions

Security fixes are generally provided for current supported releases. We aim to backport security fixes across relevant minor releases when feasible, especially if the fix can be applied without introducing breaking changes.

| Version | Supported |
| ------- | --------- |
| 2.x     | Yes       |
| 1.x     | No        |
| < 1.0   | No        |

Support decisions are flexible and may depend on severity, maintenance cost, and whether a safe non-breaking fix is possible.

If you report a vulnerability against an older unsupported version, we may ask you to verify the issue against the latest release first.

## Reporting a Vulnerability

Please do not report security vulnerabilities in public GitHub issues.

Instead, report them privately to:

- [contact@senkanthal.org](mailto:contact@senkanthal.org)

When reporting a vulnerability, please include:

- a description of the issue
- affected package version(s)
- steps to reproduce the issue
- impact assessment if known
- any suggested fix or mitigation if you have one

What to expect:

- We will review the report as soon as possible.
- We may contact you for clarification or reproduction details.
- If the report is accepted, we will work on a fix and coordinate disclosure.
- If the report is not considered a vulnerability, we will explain why.

Please avoid publicly disclosing the issue until a fix or mitigation is available.
